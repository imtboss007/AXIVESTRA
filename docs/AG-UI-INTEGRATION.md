# AXIVESTRA — AG-UI Integration

## Status
Integration branch: `feature/ag-ui-integration`.
This is an isolated integration foundation. It does not change `main`, deploy a service, enable an AI agent, or send messages.

## Upstream
- Project: https://github.com/ag-ui-protocol/ag-ui
- Protocol documentation: https://docs.ag-ui.com/
- License: MIT (verify the exact upstream revision and preserve notices when vendoring source).
- Protocol baseline: AG-UI 1.0.
- Upstream revision reviewed: `a6f2539a2ad9ba016129217637b83b7068adc6c1`.

AXIVESTRA is a React 18 + Vite application with Capacitor Android and Electron desktop packaging. The safe integration path is to consume the official TypeScript SDK packages rather than copy the entire AG-UI monorepo into the application bundle. The upstream repository remains linked above as the canonical source.

## Intended architecture

```
AXIVESTRA React / Vite UI (web, Android WebView, Electron)
        |
        | AG-UI 1.0 event stream (HTTP + SSE initially)
        v
AXIVESTRA Agent Gateway (separate service; not deployed)
        |
        +-- identity and company-scope authorization
        +-- agent orchestrator / specialist routing
        +-- read-only AXIVESTRA domain tools initially
        +-- explicit approval gate for writes and external actions
        |
        +-- Supabase / existing AXIVESTRA data services
```

AG-UI is the agent-to-application interaction protocol. It is not an LLM, database, agent orchestrator, MCP server, or complete chat UI. MCP can expose tools to agents; A2A can connect specialist agents; AG-UI streams their activity and interaction to the user.

## First implementation sequence

1. Add the official AG-UI TypeScript client/core SDKs as application dependencies.
2. Build a feature-flagged AXIVESTRA Agent Workspace, keeping existing navigation and workflows intact.
3. Add a separate gateway service that speaks AG-UI 1.0; do not put model/provider secrets in Vite, Electron renderer, Android assets, or browser storage.
4. Authenticate every run and derive company scope from the verified session on the server. Never trust a client-supplied company ID as authorization.
5. Start with read-only tools: portfolio summary, workspace search, record completeness, linked relationship summary, task/deadline summary, and financial movement explanation.
6. Add write tools only after preview → user approval → server-side authorization → idempotent execution → audit event.
7. Add domain-specific agents only behind the same gateway and policy layer.
8. Test web, Android and Windows clients, reconnect/resume, cancellation, malformed events, tenant isolation, role enforcement, auditability and offline fallback.

## Proposed AXIVESTRA capabilities

- Ask questions across the 16 existing workspaces using records the current user is authorized to access.
- Stream progress and tool activity rather than waiting for one large response.
- Explain recorded exposure, outstanding amounts, due tasks and missing information with links to source records.
- Summarize a property/deal/loan/investment/legal matter and its connected parties/documents/tasks.
- Generate a structured due-diligence checklist or report draft.
- Prepare proposed record updates, follow-ups and approval requests for human review.
- Route work to specialist agents (asset, capital, investor relations, legal operations, compliance, operations) while showing which agent is active.
- Present interactive forms, tables, charts and confirmation cards through a controlled UI component registry.

## Safety and data boundaries

- Initial tools are read-only.
- No legal conclusion, credit decision, valuation, KYC clearance or investment recommendation is autonomous or treated as verified fact.
- Distinguish user-entered records, derived calculations, external data, assumptions and forecasts.
- Enforce Supabase RLS and server-side company membership checks; UI visibility is not authorization.
- Require human confirmation for consequential writes, communications, payments, document sharing, approvals and external integrations.
- Keep model API keys, service-role keys, WhatsApp credentials and signing secrets server-side.
- Do not send private AXIVESTRA records to an external model/provider without an explicitly configured provider, lawful basis, data minimization and user/company authorization.
- Preserve local-only mode. If the agent gateway is unavailable, normal AXIVESTRA workflows must continue to work.

## Non-goals
Do not replace AXIVESTRA's 16 workspaces, local-first storage, Supabase authorization, audit model or existing workflows with an AG-UI demo app. Do not copy the full AG-UI monorepo into the production client bundle. Do not claim an AI capability is live merely because the SDK is installed.
